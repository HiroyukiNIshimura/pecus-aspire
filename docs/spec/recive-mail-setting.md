## メール種類の概念

本機能では、メールを目的と重要度に応じて次の3種類に分類する。

### 1. システムメール

アカウントの利用や安全性を維持するために必要なメール。

- パスワードリセット
- メールアドレス変更確認
- 初回パスワード設定
- 不審なデバイスからのログイン通知

システムメールは、通常のメール通知設定では停止しない。`CanReceiveEmail` の対象外とする。

### 2. 直接通知

ユーザー本人に直接関係する出来事を知らせるメール。

- 自分へのメンション
- 返信依頼・督促
- タスクの担当者変更
- アジェンダへの招待
- アジェンダの変更・中止
- 自分が担当するタスクの作成・完了

直接通知は、ユーザーが受信可否を設定できる。初期状態では ON とする。

### 3. 活動・定期配信メール

関係する対象の活動状況や、一定期間の情報を知らせるメール。

- アイテムの更新
- 一般コメント
- ワークスペース全体の活動
- 週間レポート
- 期限切れタスクのサマリー

活動・定期配信メールは、通知種別や対象ワークスペースなどを設定できる。メール通知はすべて「即時配信」とし、メール過多を防ぐため初期状態では OFF とする（※まとめて配信・ダイジェスト機能は不採用）。

### 現状実装に関する注記

現在の実装では、`CanReceiveEmail` は設定値として保存されているものの、メール送信処理で一貫して参照されていない。今後は、メールの種類を判定したうえで、システムメールは常時送信し、直接通知と活動・定期配信メールのみをユーザー設定の対象とする。

---

## 1. 設定対象外にするメール

以下は、`CanReceiveEmail` が OFF でも送信する、または別枠で扱う候補です。

| メール種別 | 理由 |
|---|---|
| メールアドレス変更確認 | アカウント操作に必須 |
| パスワードリセット | アカウント復旧に必須 |
| 初回パスワード設定 | 登録完了に必要 |
| 不審なログイン通知 | セキュリティ上重要 |
| 組織・ワークスペースへの招待 | ユーザーが参加するために必要な可能性が高い |
| メール配信停止・再開の確認 | 設定変更の結果を知らせるため |

これらまで通常通知と同じフィルタに含めると、重要なメールを見逃す可能性があります。

---

## 2. 通知種別によるフィルタ

現在のメール通知一覧をもとに、まずは以下のカテゴリが候補になります。

### タスク関連

| 設定項目 | 内容 |
|---|---|
| タスクが自分に割り当てられた | 自分が担当者になった |
| タスクが作成された | 自分が関係するアイテムに新しいタスクが作成された |
| タスクが完了した | 自分が担当・コミット・管理するタスクが完了した |
| タスクが破棄された | 関係するタスクが破棄された |
| タスクの期限が近づいた | 自分が担当するタスクの期限が近づいた |
| タスクの期限を超過した | 自分が担当するタスクが期限切れになった |
| タスクの内容が更新された | 担当タスクや関係タスクの内容が変更された |

特に「タスク作成」「タスク完了」は現在のメール通知と対応しやすいため、初期リリースの候補に向いています。

### コメント・依頼関連

| 設定項目 | 内容 |
|---|---|
| 自分への返信依頼 | `NeedReply` コメントが投稿された |
| 自分への督促 | `Reminder` / `Urge` コメントが投稿された |
| ヘルプ要請 | `HelpWanted` コメントが投稿された |
| 自分のコメントへの返信 | 自分が投稿したコメントに返信された |
| コメントが追加された | 関係するタスクにコメントが追加された |
| コメントのメンション | 自分が明示的にメンションされた |

このカテゴリでは、単に「コメント通知」とまとめるよりも、**自分宛ての依頼・督促だけを優先的に受信する**設定が有用です。

### アイテム・ドキュメント関連

| 設定項目 | 内容 |
|---|---|
| アイテムが作成された | 自分が関係するワークスペースにアイテムが作成された |
| アイテムが更新された | 担当・コミット・ウォッチ対象のアイテムが更新された |
| アイテムの件名が変更された | アイテムの名称が変更された |
| アイテム本文が更新された | 本文の変更があった |
| アイテムの担当者が変更された | 自分が担当者になった、または外れた |
| アイテムに関係者として追加された | コミッターや担当者として設定された |

本文更新は頻度が高くなりやすいため、デフォルトでは OFF、または「重要な変更のみ」を推奨します。

### ワークスペース関連

| 設定項目 | 内容 |
|---|---|
| ワークスペースが作成された | 自分が所属する組織で新しいワークスペースが作成された |
| ワークスペースが更新された | ワークスペース情報が変更された |
| ワークスペースが削除された | 所属ワークスペースが削除された |
| ワークスペースに参加した | 自分がワークスペースに追加された |
| ワークスペースのメンバーが変更された | メンバーの追加・削除があった |
| ワークスペースの権限が変更された | 自分のロールや権限が変更された |

「自分が直接関係する変更」と「所属先全体の変更」は分けた方がよいです。

### アジェンダ関連

`AgendaNotificationType` に対応して、以下が候補になります。

| 設定項目 | 内容 |
|---|---|
| アジェンダへの招待 | `Invited` |
| 参加者への追加 | `AddedToEvent` |
| 参加者からの削除 | `RemovedFromEvent` |
| アジェンダの変更 | `SeriesUpdated` / `OccurrenceUpdated` |
| アジェンダの中止 | `SeriesCancelled` / `OccurrenceCancelled` |
| アジェンダのリマインダー | `Reminder` |
| 参加者の回答変更 | 参加・仮参加・不参加などの変更 |

アジェンダのリマインダーは、通常の通知フィルタだけでなく、以下のように個別設定できると便利です。

- メールでリマインダーを受信するか
- 何分前に受信するか
- アプリ内通知のみ／メールとアプリ内通知の両方
- 自分が主催者の場合だけ受信するか

### 定期レポート関連

| 設定項目 | 内容 |
|---|---|
| 週間レポート | 前週のタスク状況やワークスペース状況 |
| 期限切れタスクのサマリー | 期限切れがある場合のみ |
| 未対応依頼のサマリー | 未返信コメントやヘルプ要請 |
| ワークスペース活動サマリー | オーナー向けの活動状況 |

週間レポートは通知というより「定期配信」なので、イベント通知とは別の設定グループに分けるのがよいです。

---

## 3. 自分との関係によるフィルタ

同じイベントでも、自分との関係によって受け取りたいかどうかが変わります。

| 関係 | 受信対象の例 |
|---|---|
| 自分が担当者 | 担当タスクの作成・更新・完了・督促 |
| 自分がコミッター | 担当アイテム内のタスク変更 |
| 自分がオーナー | ワークスペース全体の重要な変更 |
| 自分がPIN留め（関心対象） | PIN留めしたアイテムの更新、配下タスクの作成・完了、コメント追加 |
| 自分がコメント投稿者 | 自分のコメントへの返信 |
| 自分が参加者 | アジェンダの招待・変更・中止 |
| 自分が主催者 | 参加者の回答変更 |
| 自分が組織管理者 | 組織・メンバーに関する変更 |
| 自分に直接宛てられた | メンション、返信依頼、督促、ヘルプ回答 |

---

## 4. PIN留め（お気に入り）によるフィルタ

PIN（📌）は、ユーザーが自分の意思で明示的に関心を示したアイテムを表す。
そのため、担当者やコミッターでなくても、自分がPIN留めしたアイテムおよびその配下に関する変更を通知対象として選択できるようにする。

### 候補

- PIN留めしたアイテムの重要な変更（件名・ステータス・担当者変更等）
- PIN留めしたアイテムへの新しいタスク追加
- PIN留めしたアイテム配下のタスク完了・破棄
- PIN留めしたアイテム配下へのコメント追加
- PIN留めしたアイテムの本文更新

なお、アイテムを「PIN留めする／解除する」という操作自体は個人設定であるため、メール通知の対象外とする。

---

## 5. ワークスペース単位のフィルタ

複数のワークスペースに所属しているユーザーには、ワークスペース単位の設定も有効です。

### 候補

- すべてのワークスペース
- 特定のワークスペースのみ
- 選択したワークスペースではメールを受信しない
- ワークスペースごとに通知種別を変更する
- 個人作業用ワークスペースは受信しない
- 管理対象ワークスペースだけ受信する

ただし、ワークスペースごとに全通知種別を設定可能にすると設定量が急増します。初期版では、

> 通知を受信するワークスペースを選択する

程度に留めるのが現実的です。

なお、アジェンダは現在の設計上、ワークスペースではなく組織単位の機能なので、ワークスペースフィルタとは別扱いにする必要があります。

---

## 6. 通知の重要度によるフィルタ

通知種別ではなく、重要度でまとめる方法もあります。

### 重要度の例

#### 必須・重要

- 自分へのメンション
- 自分への返信依頼
- 自分への督促
- 自分が担当者になった
- アジェンダの中止
- 権限変更
- セキュリティ関連

#### 通常

- タスクの作成
- タスクの完了
- アジェンダの変更
- アイテムの担当者変更
- ワークスペースへの参加
- PIN留めアイテムの更新・タスク追加

#### 低頻度でよいもの

- アイテム本文の更新
- 一般コメント
- ワークスペース全体の活動
- メンバーの追加・削除

設定画面では、次のような簡易モードにできます。

- **重要な通知のみ**
- **自分に直接関係する通知（PIN含む）**
- **関係する対象の通知をすべて**
- **すべての通知**

これは詳細設定を開かなくても選べるため、一般ユーザーには扱いやすいです。

---

## 7. 配信タイミングと「まとめて配信」の扱い

### 方針：まとめて配信（ダイジェスト機能）は却下

一定時間（1時間、1日等）ごとに未読通知を蓄積・集約して送信する「まとめて配信（ダイジェスト）」は、通知キューの保持・バッチ集計の複雑化やリアルタイム性の欠如を避けるため、**採用せず却下**とする。

- **メール配信は原則すべて「即時配信」**（イベント発生時に送信）
- メール過多への対策は「まとめて送信」ではなく、**「受信する通知種別の絞り込み（不要な通知をOFFにする）」** で行う
- 定期配信として扱うのは、集計バッチとして独立して動作する **「週間レポート」のみ** とする

---

## 初期リリースで推奨する設定項目

「まとめて配信」を排し、シンプルに「どの事象のメールを即時受信するか」と「週間レポートを受信するか」に整理します。

全体のUXとして、**基本設定（プリセット選択）** を用意し、**「カスタム」を選んだ場合のみ詳細な通知項目のON/OFFを個別に設定できる** 2段構えの構成とします。これにより、普段は手軽にモードを選べ、こだわりたいユーザーだけが詳細設定を行えます。

---

### 1. 基本設定（配信モードの選択）

メール通知を受信する（マスターON）場合、ユーザーは運用スタイルに合ったモードを選択します（配信停止はマスタースイッチのOFFで実施）。

| モード / 設定項目 | 説明・挙動 |
|---|---|
| **重要通知のみ** | 自分へのメンション・返信依頼・督促、期限切れ、アジェンダ中止など、即時対応が必要なものだけに絞り込む。 |
| **標準（推奨）** | Coati推奨のデフォルト設定（担当タスク、PINアイテム、アジェンダ通知を含む）。 |
| **カスタム** | **通知項目ごとに個別のON/OFFを自由に設定する**（選択時に詳細項目エリアが展開）。 |

※ **週間レポート**の受信（ON/OFF）および**対象ワークスペース**（全WS / 選択WS）は、モード選択とは独立して設定可能です。

---

### 2. モードと通知設定の連動イメージ

```
[メール通知設定]
  │
  ├── 🔘 メール通知を受信する (マスター ON / OFF)
  │     │  ※ OFFの場合、システムメールを除く全メール配信を停止
  │     ▼ (ONの場合のみ以下を展開)
  │
  ├── 🔘 配信モード選択
  │     ├── ( ) 重要通知のみ ─────── [プリセット適用（変更不可）]
  │     ├── (⊙) 標準（推奨）  ─────── [推奨プリセット適用（変更不可）]
  │     └── ( ) カスタム     ─────── ▼【詳細設定エリアを展開】
  │                                    各通知項目のトグルを自由にON/OFF可能
  │
  ├── ☑ 週間レポートを受信する（独立設定）
  │
  └── 📁 対象ワークスペース
        (⊙) すべてのワークスペース
        ( ) 選択したワークスペースのみ
```

---

### 3. 詳細設定項目（「カスタム」選択時に設定可能な項目一覧）

「カスタム」モードを選択した場合、または「標準」プリセットの内容として適用される各項目の内訳とデフォルト値です。

| カテゴリ | 通知項目 | 標準モードの初期値 | カスタム時の設定 |
|---|---|:---:|:---:|
| **セキュリティ** | アカウント・認証関連（システムメール） | 送信 | 固定（変更不可） |
| **自分宛て** | 自分へのメンション | ON | ON / OFF |
| | 返信依頼（`NeedReply`） | ON | ON / OFF |
| | 督促（`Urge` / `Reminder`） | ON | ON / OFF |
| | ヘルプ要請（`HelpWanted`） | ON | ON / OFF |
| **タスク** | 自分が担当するタスクの作成 | ON | ON / OFF |
| | 自分が関係するタスクの完了 | ON | ON / OFF |
| | 自分が担当するタスクの期限超過 | ON | ON / OFF |
| **アイテム・PIN** | PIN留めしたアイテムの更新・タスク追加 | ON | ON / OFF |
| | 担当・コミット対象アイテムの更新 | OFF | ON / OFF |
| | アイテム本文の更新 | OFF | ON / OFF |
| **コメント** | 一般コメントの追加 | OFF | ON / OFF |
| **アジェンダ** | アジェンダへの招待・変更 | ON | ON / OFF |
| | アジェンダの中止・リマインダー | ON | ON / OFF |
| **ワークスペース** | ワークスペース全体の活動・メンバー変更 | OFF | ON / OFF |

---

### 4. 対象範囲（スコープ）

上記で設定した通知カテゴリを適用するワークスペースの範囲を指定します。

- **すべてのワークスペース**（デフォルト）
- **選択したワークスペースのみ**（特定のワークスペースでのみメールを受信し、それ以外はミュート）

※ アジェンダ通知およびシステムメールは組織単位のため、ワークスペース選択の対象外（常に有効）。

## プリセットごとの設定値比較

| 通知項目 | 重要通知のみ | 標準（推奨） | カスタム |
|---|:---:|:---:|:---:|
| システムメール（セキュリティ等） | 送信 | 送信 | 送信（固定） |
| 自分宛て（メンション・依頼・督促・ヘルプ） | **ON** | **ON** | 自由 |
| 担当タスクの期限超過 | **ON** | **ON** | 自由 |
| アジェンダ中止・リマインダー | **ON** | **ON** | 自由 |
| 自分が担当するタスク作成 | OFF | **ON** | 自由 |
| 自分が関係するタスク完了 | OFF | **ON** | 自由 |
| PIN留めアイテムの更新・タスク追加 | OFF | **ON** | 自由 |
| アジェンダ招待・変更 | OFF | **ON** | 自由 |
| その他（本文更新、一般コメント、WS活動等） | OFF | OFF | 自由 |

「重要通知のみ」と「標準（推奨）」で大半のユーザーニーズをカバーしつつ、業務特性に応じて「カスタム」で細かく調整できるため、UIのシンプルさと柔軟性の両立が可能です。
